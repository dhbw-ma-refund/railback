## What was done

Went with **Path A**. Three things shipped and are on `database` branch now.

### 1. `node/src/types.ts` — DTO layer + `Db` interface

Defines the domain types that the adapter exposes:

```typescript
User, UserAuthLookup, UserAdminView, Admin, Ticket, SepaMandate
```

And the repo interfaces the backend wires against:

```typescript
UserRepo, AdminRepo, TicketRepo, MandateRepo, Db
```

No physical attribute names (`pk`, `sk`, `gsi*`) anywhere in these types.

### 2. `node/src/adapter.ts` — `DdbBackend`

Implements `Db`. Each method:
- calls the underlying connector method
- calls `.unwrap()` — throws the wrapped error on `Err`, returns the value on `Ok`
- maps the raw DDB item to a typed DTO (strips physical keys, camelCases domain attrs, extracts semantic IDs from `pk`/`sk`)

`ConflictError` is re-exported from the adapter so callers can catch it by type.

Method name translations from connector → `Db` interface:

| Connector | Adapter |
|---|---|
| `user.get(email)` | `users.getByEmail(email)` |
| `user.getForAdmin(email)` | `users.getByEmailAdminView(email)` |
| `ticket.checkBarcodeDuplicate(uid)` | `tickets.findByBarcodeUid(uid)` |
| `ticket.listEmailPending(limit)` | `tickets.queryEmailPending(limit)` |
| `mandate.stampPain008Built(e,t,b,s,at)` | `mandates.stampPain008Built(e,t,{batchId,s3Key,builtAt})` |

`deleteUser` and `deleteTicket` are top-level on `Db` (not under a repo), same as your connector.

The `put` / `update` methods still take `Record<string, unknown>` — the write-path types (`NewUser`, `ProfilePatch`, etc.) are your types and should stay in your `lib/src/types/`. When you share those, the adapter signatures can be tightened.
